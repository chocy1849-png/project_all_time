# M13-03 font integrity investigation

## Reproduction and cause

In Unity 6000.3.21f1 Play Mode, opening the production `VNSaveLoadModal` through `VNSaveLoadController.OpenSave()` showed squares in empty slots and existing technical checkpoint metadata. No save was written. [Before](M13_Evidence/M13_03_FontPatch/m1303_font_save_before.png) and [after](M13_Evidence/M13_03_FontPatch/m1303_font_save_after.png) show the same production view and existing slots. These images contain the displayed technical slot timestamps and are included as explicitly requested evidence.

The actual `VNSaveSlotItem` `EmptyStateRoot/EmptyStateText` runtime string was `Empty slot`, code points `0045 006D 0070 0074 0079 0020 0073 006C 006F 0074`; before the fix the TMP character stream was `0045 006D 25A1 0074 25A1 0020 0073 006C 006F 0074`. The string was correct and the `p` and `y` glyphs were replaced at rendering. `NormalMetadataRoot/ChapterText` had `m5_technical` and `SceneTitleText` had `M5 Technical Checkpoint A/B`, rather than replacement characters in their source strings.

Affected slot text used `NotoSansKR-Regular SDF`, `NotoSansKR-Regular Atlas Material` with material main texture matching atlas 0. Its source was the tracked `Assets/_Project/Fonts/NotoSansKR/NotoSansKR-Regular.ttf`; atlas population was Dynamic, 1024×1024, one atlas, multi-atlas disabled, with no local fallbacks. A cloned asset with the same current full atlas failed `TryAddCharacters("py")` with multi-atlas disabled, then succeeded and grew to two atlases after enabling it. This demonstrates atlas capacity as the observed failure, rather than a corrupted string or Pretendard assignment. Static M10 prologue text and the dedicated dynamic Pretendard/M13 fonts have separate configurations; no blanket replacement was made.

`VNProductionFontBootstrap` enables multi-atlas for the existing dynamic Noto resource before scene loading, when its source font is present. It does not write the original asset, alter TMP Settings, clear a user's cache, or change font assignments. On a new Editor Play session, the actual slot text resolved to the original ten code points, multi-atlas was true and two atlases existed. A scan of active Save/Load slot texts including `m5_technical`, `M5 Technical Checkpoint A/B`, slot numbers, timestamps and Korean placeholder text found zero U+25A1 replacement characters after `ForceMeshUpdate`.

## Automated and build results

Six focused font tests passed: production prefab assignment/material/source, four fresh isolated dynamic fonts (Noto and Pretendard 400/500/600) with the requested mixed Korean/English/keyboard corpus, actual TMP text generation with no U+25A1 and multiple atlas growth, and a separate actual TMP fallback resolution test. These fixtures create/destroy their own font assets and textures; they do not modify player saves or the tracked Noto asset. The combined M1303 suite was **17 passed / 0 failed**. Separate Save/Load UI filtering ran **8/8**, Records **104/104**, and Dialogue session (including backlog semantics) **16/16**. A `VNBacklog` name filter matched zero tests; the Dialogue session and full suite include backlog-related coverage. The corpus is checked against source coverage and generated TMP character streams; the production font's complete fallback graph and every possible runtime name have not been exhaustively proved.

The first full run produced **578 passed / 1 failed**: `ExpandedGraph_ValidatesAndRestoresReconstructedS005SaveThroughCoordinator` timed out at its integration coroutine. A focused retry and a second full run repeated that timeout. After a graceful Editor restart the same test passed alone and the fresh full run completed **580 passed / 0 failed / 0 skipped / 0 inconclusive**. The reason the first Editor session timed out was not established.

A new Windows x64 Player build at `Builds/M13_03_FontPatch/ProjectAllTime.exe` succeeded with **0 errors, 486 warnings**. The standalone Player was not launched: previous Computer Use approval rejected the isolated executable. Therefore build success is not evidence of clean-Player rendering or physical input. User physical Player verification remains required.
